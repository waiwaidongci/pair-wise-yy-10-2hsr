# zfl-42 漆线雕 · 线材回潮准入与贴线复核台

独立静态前端应用，直接用浏览器打开 `index.html` 即可使用（localStorage 持久化，无需服务端）。

## 三个业务文件

| 文件 | 职责 |
| --- | --- |
| `rules.js` | 业务规则层。纯领域逻辑，不碰 DOM / 不直接持久化；所有写操作在事务副本上执行，返回类 HTTP 结果 `{status, code, message, data}`，非 2xx 不落盘。 |
| `storage.js` | 存储层。localStorage 读写、版本化数据结构、演示种子、`transact(fn)`（仅 2xx 提交，冲突整体丢弃）。 |
| `page.js` | 页面层。DOM 渲染与表单交互（建档 / 领料 / 复检 / 进度 / 更正 / 复核 / 刷新），规则判定与持久化全部委托上两层。 |

## 核心规则

- **批次占用锁**：同一线材批次在某件贴线未完成（进度 < 100%）前，不得再领给第二件 → 返回 `409 BATCH_IN_PROGRESS`，且本次不写入；贴线登记 100% 后占用释放，可领给第二件。
- **回潮准入闸**：含水率 > 12%，或距上次复检超过 7 天 → 只能留检，领料返回 `422 HOLD_FOR_INSPECTION`，不写入；复检合格（`RECHECK_PASS`）后解除。
- **更正版本化**：胎体材质、纹样主题或已领批次被更正后，旧贴线进度立即清零失效，新版本回到「待复核」；旧版冻结留档（含冻结时进度与更正原因），不进当前队列。换领的目标批次须重过准入与占用校验，任一不过整笔更正回滚、旧版保留。
- **领用幂等**：同件当前版本重复领用同一批次，沿用首次领用结果（`200 ISSUE_REPLAY`，不重复发料、不新增日志）；并发双发共享同一在途 Promise（页面提供「模拟并发双发」按钮验证）。
- 其他：待复核件须先复核通过才能领料（`409 PENDING_REVIEW`）；已领他批且贴线未完成不得另领（`409 PIECE_ALREADY_ISSUED`）。

## 页面功能

- 工件建档、线材批次建档（建档即做准入判定）。
- 领料（下拉选项标注合格可领 / 留检原因 / 占用中）。
- 线材复检并按复检日期重新判定（刷新核对状态按今日重算 7 天期限）。
- 贴线进度登记（100% 释放批次）、胎体/纹样/已领批次更正、复核通过。
- 四列看板（待领料 / 贴线中 / 贴线完成 / 待复核）、批次准入列表、旧版留档列表、请求流水（含 409/422 留痕）。
- JSON 导出与「重置演示数据」。

## 测试

- `node test-rules.js`：规则层 56 项断言（VM 沙箱模拟 window/localStorage），覆盖 409 不写入、422 留检、并发幂等、更正版本化与回滚等。
- `node test-page.js`：jsdom 页面集成 32 项断言（jsdom 需本地安装，如 `npm i jsdom`）。
